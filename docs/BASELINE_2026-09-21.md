# The Chef — Baseline de reconciliación 2026-09-21

## Objetivo
Crear una única fuente de verdad reproducible para The Chef antes de continuar con nuevas funciones.

## Fuentes reconciliadas
1. `main` en commit `74879ee24722e1b6fdf488a3d16ae7a2c6280443` (rollback del 8/09/2026).
2. Rama `backup-before-rollback-2026-09-09` en commit `d5f78bb07fcd79af5d69bee2dfd84c092c6fe81f`.
3. Documento maestro actualizado el 11/09/2026 con 104 puntos de revisión en 17 bloques.
4. Decisiones posteriores al documento maestro:
   - ficha de receta: título → resumen → foto → nutrición → opciones;
   - la foto debe estar preparada antes de presentar la receta terminada;
   - la planificación semanal/nutricional incorporada al piloto privado se considera experimental y no bloquea CORE V1.
5. El piloto privado/Site del 11/09/2026 debe compararse contra esta rama cuando su código fuente quede accesible. Hasta entonces no se presume que sus cambios existan en GitHub.

## Estado técnico verificado
- `main` está por detrás de la rama de respaldo.
- La rama de respaldo contiene `package.json` versión `1.0.0-rc2`.
- La rama de respaldo dispone de build TypeScript/Vite, auditoría estática Fase 1 y auditoría de vulnerabilidades críticas de producción en CI.
- La rama de respaldo genera la imagen de receta de forma perezosa dentro de `RecipePage`.
- La ficha de receta de la rama de respaldo muestra actualmente título → foto → descripción → metadatos → nutrición, por lo que NO cumple todavía la decisión posterior título → resumen → foto → nutrición → opciones.
- `ResultsPage` genera la receta completa al elegir una propuesta, pero navega a la ficha sin esperar a que la imagen quede preparada.

## Regla de fuente de verdad
Desde esta reconciliación:
- GitHub será la fuente de verdad técnica.
- Ninguna función se considera implementada por estar descrita en un chat, documento, Site o mensaje de validación.
- Un requisito pasa a Implementado solo tras prueba reproducible sobre un commit identificado.
- No se fusionará a `main` hasta superar el gate CORE V1.
- No se eliminarán ramas históricas hasta cerrar la beta privada.

## Alcance CORE V1
CORE V1 debe cubrir, como mínimo:
- ¿Qué quieres que te prepare?
- Abre la nevera / cocina con lo disponible.
- Texto y voz.
- Comensales, tiempo, dificultad, estilo/cocina/producto/técnica/utensilios/restricciones cuando proceda.
- Dos propuestas diferenciadas.
- Uso de disponibles, prioritarios, básicos, faltantes, opcionales y sustituciones.
- Receta completa, coherente, escalable y reproducible.
- Ingredientes, mise en place, recomendaciones, puntos críticos y elaboración.
- Modo cocina y temporizador.
- Favoritos, historial y Mis recetas.
- Lista de compra.
- Despensa y nevera V1.
- PDF.
- Experiencia móvil utilizable.

## Funciones no bloqueantes para CORE V1
- Foto Receta.
- Crear tu receta.
- Técnicas.
- Multidioma completo.
- Planificación semanal.
- Nutrición avanzada.
- Colecciones.
- Personalización avanzada.

Pueden conservarse si funcionan, pero no retrasarán el cierre del núcleo.

## Gates
### Gate R0 — Reconciliación documental
- rama única de trabajo;
- fuentes y decisiones posteriores documentadas;
- discrepancias conocidas registradas.

### Gate R1 — Reconciliación funcional
- incorporar las decisiones posteriores de ficha/foto;
- resolver cualquier diferencia recuperable del piloto privado;
- no perder funciones válidas de RC2.

### Gate R2 — Validación técnica
- `npm run audit:phase1`;
- `npm run build`;
- `npm audit --omit=dev --audit-level=critical`;
- pruebas de regresión de CORE V1.

### Gate R3 — Dispositivos
- iPhone/Safari;
- Android/Chrome;
- PC;
- cámara, micrófono, teclado, zoom y temporizador en foreground/background.

### Gate R4 — Beta privada
- cero bloqueantes conocidos;
- documentación de limitaciones no bloqueantes;
- versión y commit identificables;
- despliegue privado reproducible.

## Pendencia crítica
El código exacto del piloto privado del 11/09/2026 no se ha localizado en GitHub ni en Google Drive. Por tanto, no se utilizará como fuente técnica implícita. Sus decisiones funcionales conocidas se reimplementarán explícitamente en esta rama y se validarán una por una.

## Evidencia de validación
En la rama de reconciliación se ha ejecutado GitHub Actions con resultado satisfactorio para:
- instalación de dependencias;
- auditoría de vulnerabilidades críticas de producción;
- auditoría estática Fase 1 ampliada;
- compilación TypeScript/Vite.

La prueba de dispositivos físicos y la validación funcional completa siguen pendientes y no se consideran sustituidas por este resultado.
